## Migrations

À appliquer sur le projet Supabase après sauvegarde, dans l’ordre du dossier `supabase/migrations` :

- `20261003100000_security_foundations.sql` — limitation de débit et journal d’audit (lot 0).
- `20261003120000_catalog_admin.sql` — champs produit, caractéristiques, bucket `product-images`, fonction `admin_save_product` (lot 2).
- `20261014100000_order_requests.sql` — demandes de commande : coordonnées figées, clé d’envoi, raisons d’attention, interrupteur `orders_open` (fermé), fonctions `submit_order_request`, `admin_accept_order`, `admin_cancel_order` (lots 4 et 5).
- `20261014120000_email_outbox.sql` — file et journal des emails, fonction `claim_outbox_email` réservée au serveur (lot 6).
- `20261015100000_contact_requests.sql` — demandes clients et leurs photos, droits de l’admin limités au suivi, bucket privé `request-photos`, lien des emails vers les demandes (lot 7). À appliquer **après** `20261014120000_email_outbox.sql`.
- `20261016100000_review_requests.sql` — demandes d’avis par lien (empreinte du jeton seulement), un avis par commande, fonction `submit_review` réservée au serveur (lot 8).
- `20261017100000_legal_customers.sql` — versions légales publiques et non modifiables, version des CGV acceptée par commande, fonction `admin_forget_customer` (lot 9).
- `20261018100000_delivery.sql` — zones de livraison (actives seulement avec un tarif), distance et zone sur les commandes, réglages du retrait (lot 10).
- `20261019100000_order_changes.sql` — statut « modification proposée », propositions au client (`order_proposals`, empreinte du jeton seulement), ventes manuelles (`source`, client facultatif), fonctions `admin_propose_order`, `respond_order_proposal` (réservée au serveur), `admin_resolve_order_proposal`, `admin_create_manual_order` ; `admin_cancel_order` et `admin_forget_customer` mises à jour (fin du lot 5). La nouvelle valeur d’enum n’est utilisée que dans des fonctions plpgsql : le fichier passe d’un seul tenant.

Constaté le 14 octobre en lecture seule : toutes les migrations jusqu’à `20261012130000_public_catalog_invoker.sql` sont présentes sur le projet distant (ne pas les rejouer : elles échouent sur des objets déjà créés, et `catalog_admin` remettrait l’ancienne vue du catalogue) ; `20261014100000_order_requests.sql` a été appliquée ensuite le même jour. Les migrations des lots 6 à 10 sont appliquées en ligne (vérifié en lecture seule le 15 octobre : tables `legal_versions` et `delivery_zones`, colonnes ajoutées à `orders`). Reste `20261019100000_order_changes.sql` (fin du lot 5) : sans elle, les boutons « Proposer une modification » et « Nouvelle vente » renvoient une erreur, le reste fonctionne. Toutes passent sur une base neuve (PGlite, 15 octobre).

## Mise en service de l’accès administrateur

1. Appliquer les migrations, puis renseigner `.env.local` (voir `.env.example`), dont `SUPABASE_SERVICE_ROLE_KEY` et `RATE_LIMIT_SECRET`.
2. Dans Supabase : *Authentication → Sign In / Providers* : fournisseur **Email activé**, mais **inscriptions désactivées** (« Allow new users to sign up » décoché). *Authentication → URL Configuration* : *Site URL* = l’adresse du site ; ajouter `<site>/auth/confirm` aux *Redirect URLs*. En local, `supabase/config.toml` fait déjà ces réglages.
3. Créer le compte : `npm run admin -- create <email>` (ou `grant <email>` pour un compte existant). Aucun mot de passe n’est affiché.
4. Sur le site : « Espace apiculteur » → « Mot de passe oublié » pour choisir le mot de passe, puis se connecter.
5. Vérifier à tout moment : `npm run admin -- check <email>` (lecture seule).

Le lien de réinitialisation par défaut doit être ouvert dans le navigateur qui a fait la demande. Pour l’ouvrir ailleurs, personnaliser le gabarit d’email Supabase avec `{{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=recovery&next=/nouveau-mot-de-passe`.

## Environnement local

- `npx supabase start` (Docker requis) : base, Auth, Storage et boîte mail de test Mailpit (http://127.0.0.1:54324). Migrations et seed appliqués au premier démarrage.
- `.env.local` : URL `http://127.0.0.1:54321` et clés locales affichées par `supabase start` ; `NEXT_PUBLIC_SITE_URL=http://localhost:3000` (port autorisé pour les liens de connexion).
- Lancer le site avec `npm run dev` (port 3000).
